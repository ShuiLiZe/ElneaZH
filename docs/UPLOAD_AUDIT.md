# 上传审计（UPLOAD_AUDIT）

对象：ElneaZH 汉化版对 althi 服务器发出的每一条 `sns04/*.php` 请求，逐接口逐字段列出
**可能和原版英文客户端不同**的内容，给风险与建议。

本文件只写文档，不改行为。所有数字可由 `python tools/acc_forensics.py` 复现，
断言由 `python tools/acc_forensics.py --selftest`（10 项）与 `python tools/verify_upload_audit.py` 校验。

---

## 0. 证据基础（先说清楚哪些能查、哪些查不到）

真机样本：`test/frida-gadget` 分支实测抓包整理出的 28 条记录（17 条去重后互异的密文，
落盘为 `tools/acc_fixtures.json`，只含 `acc=` 的**密文**字节，不含任何明文/账号）。
接口覆盖：`check.php / login.php / gift.php / read.php / mail.php / pvp.php / kpi.php / recov2.php`。

**关键结论（决定了这份审计的写法）：`acc=` 是 16 字节分组、每块重新加权的密文，密文里
读不出字段值。** 依据：

| 观测 | 数值 | 含义 |
| --- | --- | --- |
| 所有 body 长度 | 64/96/128/160/224/256/1728，全部 16 的倍数 | 分组密码，不是流密码 |
| 136 对同/异长度 body 两两异或后「可打印 ASCII 占比」最高值 | 0.289 | 若是流密码 XOR，同接口两条应 ≈1.0；不是 |
| `read.php` 7 条 160B body 的逐块去重 | 偏移 0..3 = 1 种；4..5 = 7 种；6..9 = 3 种 | 固定会话前导 + 逐请求载荷 + 小枚举态 |
| 跨接口重复块 | `gift/read/mail/pvp/recov2` 共享偏移 0..1；`read`(160B) 与 `mail`(128B) 共享末两块 | 共享的是会话前导与公共尾巴，不是被翻译的字段 |
| `acc=` 线上长度 | 纯由密文长度决定（`base64` + `%2B`/`%2F` 双写），64B→88 字符，1728B→2304 字符 | `acc=` 本身没有额外封装字段 |

因此，凡是「我们发的值 vs 原版应是」需要看明文的行，本审计给出**发得出该字段的 Java/C# 侧来源**
＋**结构性风险判断**，而不臆造明文值；标 `明文待验` 的行，抓包侧只需在
`Cipher::EncryptRJ256` 入口（VA `0x18ad7e4`）打一条明文日志即可补齐——这正是我们
（`inj/.../NameFix` 与 `native/elneagate`）已经在 hook 的地址，工具链具备条件，无需新装。

## 1. 加密层本身

| 字段 | 我们发的值 | 原版应是 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| `acc=` 密文算法 | 游戏原生的 `Cipher::EncryptRJ256`（我们只是 hook 明文，不替换算法） | 同一函数 | 无 | 保持现状：**不要**自造加密实现 |
| `acc=` 是否带版本/渠道标记 | 密文首 16 字节里的固定前导（同会话所有接口一致） | 同 | 无 | 无需处理 |
| 明文长度 | 由 body 长度决定（见上表） | 同 | 低。名字过滤后 UTF-8 变长会让 `kpi.php`（存档上传，1728B，最大）体积变化 | 已在 `NameFix.filterNames` 限制单槽 ≤255 字节、整体增长 ≤4×+4KB，且结构校验过才写回；超限退回拼音 |
| 空/异常明文 | 过滤器返回原对象（不改造） | — | 无 | 保持 |

## 2. 逐接口字段表

来源列中：`C#` = 游戏原生（我们未改，只在 `Metadata` 里查过字面量）；`Java` = 汉化注入层
（`inj/com/shuilize/elneazh/inj/*`）；`hook` = `libelneagate` 原生层。

### 2.1 `check.php`（64B，4 块密文）

| 字段 | 我们发的值 | 原版应是 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| 会话/账号标识 | C# `althi_uniq` / `uuid`（`Backup.java` 已确认这两个键是登录凭证，`global-metadata` 索引 10282 / 15217） | 同 | 无（值来自本地 prefs，未汉化） | 无 |
| 语言/地区 | 未见独立字段（64B 只够固定前导 + 账号 + 校验） | 同 | 低：若服务器端按包名/渠道判区服，改包名会落到别的区 | 见 §3 包名行 |
| 客户端版本 | C# 常量 | 同 | 低 | 不要改 `version` 字面量 |

### 2.2 `login.php`（224B 与 256B 两种，14/16 块）

| 字段 | 我们发的值 | 原版应是 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| 账号名 `user_name` / `user_id`（metadata 索引 15200/15196） | C# 原样发送玩家输入的登录名 | 同 | **中**：玩家若用中文名注册（或我们用 SaveNames 写回中文），登录名 UTF-8 变长 → 服务端可能截断/拒绝 | 上传闸门只转换**存档内的显示名**，登录名不做转换；若发现中文登录名被拒，在登录框旁给一行提示（不改协议） |
| 密码 | C# 原样 | 同 | 无 | 不碰 |
| `login_key` / `token`（12937 / 14859） | 本地 prefs 原样 | 同 | 无 | 无 |
| 换身份后首次登录 | `Identity.java` 抹掉 `uuid`/`login_key` 后由 `UuidPlugin` 生成新 uuid | 原版是设备首次安装生成的 uuid | **中**：`UuidPlugin` 生成的 uuid 若格式与原版不同（长度/大小写/字符集），可能与服务器 uuid 表冲突策略不同 | 抓一条明文确认 uuid 长度与字符集（`明文待验`）；不符时按原版格式重发 |
| 重复登录回执 | 服务器回 `already login!`（样本已见） | 同 | 无 | 这是换身份流程的正常分支，`Identity` 已处理 |

## 3. 与「客户端身份」相关的全局字段（可能比字段更致命）

| --- | --- | --- | --- | --- |

| 签名 | 自签名（替换为我们的 keystore，`app/keystore/`） | althi 官方签名 | **中**：若服务端做签名校验/风控，这是唯一无法隐藏的差异 | 已经能正常登录说明当前不校验；不要在同一 uuid 上频繁换签名 |

## 4. 名字转换闸门（唯一的「我们主动改字段」的地方）

规则（与 `NameFix.filterNames` / `UploadNames` / `native/elneagate/eg_names.c` 一致）：

1. NPC 名：中文 → `names.tsv` 里的英文原名（1724 行，其中 1674 行双向可逆；12 处中文重名
   指向多个英文名，取表内第一条，因此这 12 个名字**不可逆**——属于已知损失，本地显示不受影响）。
2. 玩家名：中文 → camel 拼音（`赵四` → `ZhaoSi`），保证 ASCII 且长度可控。
3. 槽长度字节按转换后 UTF-8 字节数重算，允许变长，上限 255；转换后总长超过 4×+4096 则放弃压缩改道。
4. 转换后仍含 CJK → `WARN name filter left N CJK char(s) in <where>`（`verify_upload_names.py` 断言此日志存在）。

| 字段 | 我们发的值 | 原版应是 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| NPC 名槽 | 英文原名（表内） | 英文原名 | 低：表外 NPC 名（未来更新）会保留中文并 WARN | 版本更新后重跑 `tools/names_map.py` 补表 |
| 玩家名槽 | camel 拼音 | 玩家自己起的英文名 | **中**：拼音与原版「玩家可输入任意英文/数字」不同，可能与好友搜索、举报等按名字索引的功能对不上 | 已在 `UPLOAD_AUDIT` 记明；若将来要更贴近原版，改为「允许玩家单独设置上传用英文名」 |
| 家族名槽 | 同上 | 同上 | 同上 | 同上 |
| 空名/纯符号名 | 原样 | 原样 | 无 | 无 |

## 5. 优先级清单（要动就先动这些）

1. **`kpi.php` 存档里的名字**（已缓解，仍是最可能暴露的一条）→ 保持 WARN + 双向自测。
2. **换身份生成的 `uuid` 格式**（`明文待验`）→ 一条明文日志即可确认，成本最低。
3. **中文登录名**（`login.php`，`明文待验`）→ 若被拒，加 UI 提示而不是改协议。
4. **签名不一致**（无解，只能避免反复换签名）。
5. 其余字段均为原生直传，无需动作。

python tools/acc_forensics.py --selftest # 10 项结构断言
python tools/verify_upload_audit.py      # 文档与样本一致性校验
